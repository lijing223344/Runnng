## 0. 总体结论

**底子很好**：纯黑沉浸式主题方向统一，`DS` 设计令牌（色板/字阶/间距/圆角/透明度）已建立，`TrainingVisualStyle` 提供了可复用的卡片/按钮原语，空态样式全 App 一致，训练数字使用 rounded 粗体可读性强。这是一个「有设计系统」的 App，不是拼凑出来的。

**核心问题集中在两处**：

1. **强调色失控（视觉）**：设计系统定义 4 个功能域色，但页面实际出现了 **≥10 种色相**（蓝/橙/绿/青/品红/薰衣草紫/靛蓝/黄/琥珀/红），根源是 `PaceRunSetupView.swift` 等直接使用 SwiftUI 语义色 `.purple` / `.cyan` / `.indigo` 绕过令牌。
2. **长表单与训练页的操作流（效率）**：编辑器表单长达约 3 屏，而「保存」固定在顶部；训练进行中界面下半屏大面积留白，缺少 glanceable（一眼可读）的进度与下一步信息——这是训练类 App 最核心的体验。

**无障碍是当前最严重的短板**：所有编辑器页的「取消/保存/返回/+」胶囊按钮未暴露 accessibility 标签，VoiceOver 用户无法导航核心编辑流（同时导致 UI 自动化只能按坐标点击，回归测试脆弱）。

**分级汇总**：P0 × 7（功能流/可用性缺陷）、P1 × 8（视觉一致性问题）、P2 × 6（打磨项）。

## 1. 视觉系统审计

### 1.1 色彩体系 —— 最大的一致性问题

**现状**：`DesignSystem.swift` 定义了清晰的 4 功能域色 + 语义色：

| 令牌 | 色值 | 用途 |
|---|---|---|
| `paceRun` | 皇家蓝 (0.18, 0.45, 0.96) | 节奏跑 |
| `interval` | 橙 (1.00, 0.50, 0.05) | 间歇跑 |
| `model400` | 绿 (0.15, 0.82, 0.38) | 400米模型 |
| `miniHurdle` | 青 (0.00, 0.72, 0.78) | 小栏架 |

**但实际页面**（证据：截图 03/04/10/11）出现了令牌之外的色相，根源是硬编码语义色：

- 节奏跑编辑器内：「分段距离」用 `Color.purple`（品红观感）、「跑休倒计时」用 `Color.cyan`、「训练强度」用 `.indigo`（薰衣草紫观感）——一屏 5 种色相（截图 03/04）。
- `PaceRunSetupView.swift:576,584,1068,1080,1095,1112,1160,1179…` 共 10+ 处 `.cyan` / `.purple` / `.indigo` / `.orange` / `.green` 硬编码。
- 历史页统计卡顶条（截图 19）用蓝/绿/橙，与「已停止」琥珀徽章并存，第 4 种色相进入。
- 同一语义「训练强度 100% 选中」：节奏跑编辑器里是薰衣草紫（截图 04），400米模型页里是绿色（截图 13）——同义不同色。

**建议**（详见 §4 Phase B）：
- 建立「域内配色函数」：每个功能域只允许 `主色 + 主色.opacity(浅/深) + 中性 + 语义色`。
- 编辑器内的「区块色」（总距离/分段距离/倒计时等）改为**同一功能域主色的明度变化**（如 paceRun 100% / 75% / 50%），或干脆统一用 `DS.Colors.cardHover` + 主色仅做图标点缀——推荐后者（更符合「Linear/Stripe 式克制」，也是 DesignSystem 注释声明的方向）。
- 「训练强度」全 App 统一一种颜色（建议归属功能域主色或固定琥珀 warning）。
- 「跑休/倒计时」可用固定冷色 token（如新增 `DS.Colors.rest`），语义「休息=冷色」是有意设计，保留但令牌化。

### 1.2 字体与数字

**好的**：训练数字 `timerLarge/timerMedium`（rounded, black）辨识度高；速度/用时/里程徽章统一 rounded bold（截图 07/12）。

**问题**：
- 设置页版本号「2.0（4）」使用等宽字体（截图 20/25），与该页其他 SF 字体行不一致；且英文环境下出现**全角括号**（截图 25）——本地化字符串问题。
- 首页大标题 `tracking(-1)` 手工字距对中文无意义（中文无字距优化收益），仅对英文有效——可接受，但建议统一到 Typo 令牌而非散落 `Font.system(size:…)`。目前大量视图绕过 `DS.Typo` 直接写 `size 22/18/15/13`，字阶已事实上分叉（P2，随改随收）。

### 1.3 布局与栅格

- **首页**（截图 01）：4 张 140pt 入口卡 + 底部自绘 tab 栏。第 4 张卡默认视口下被 tab 栏遮住约一半（`padding(.bottom, 100)` 不足；tab 栏实际高度 + safe area ≈ 90–120pt）。**首屏只完整露出 2.5 张卡，第 4 功能「小栏架」曝光度受损**。
- **空态**（截图 02/09）：图标圆 + 标题 + 副标题 + CTA，节奏跑/间歇跑完全同构——好。唯一小问题：空态 CTA 与右上角 + 按钮双入口重复（可接受，不算问题）。
- **小栏架页**（截图 15–18）：信息密度高但秩序良好；两列指标卡网格、Clark/Mann 区间行、21 行摆放表均对齐。测量示意图为浅色底医疗插画（截图 18），在纯黑主题中形成强反差白块——建议加圆角+边框卡片化，或提供深色版（P2）。
- **导航栏滚动穿透**（截图 16/17/18 顶部可见）：滚动时大标题区域无材质背景，内容文字与状态栏/标题重叠。编辑器（截图 04）因顶部是纯黑渐变则不明显。建议统一给滚动页 nav 区加 `.ultraThinMaterial` 或渐变遮罩。

### 1.4 导航模式

- 首页自绘 3 tab（训练/历史/设置）：可用，但与系统 tab 栏相比缺少 hit target padding 和选中动效；文字 10pt 偏小（HIG 建议 ≥11pt 正文级）（P2）。
- **设置子页导航模式不统一**（P0-6）：「提示音设置」是 `取消/保存` 双胶囊（截图 21），「语言设置」只有右上 `完成`、无返回（截图 22），且语言切换**即时生效**（选英文后标题立刻变 Language）——即时生效 + 保存制混用，心智模型矛盾。登录页（截图 23）又是 `取消` 单胶囊。三种模式应统一。
- 语言选择行**双重选中指示**：左侧蓝色圆勾 + 右侧对勾同时出现（截图 22/24），保留其一即可（P1）。

## 2. 操作流审计

### 流 1：开始一次节奏跑（核心流）
首页 → 「节奏跑」卡 → （首装需：+ → 填 3 屏表单 → **滚回顶部点保存**）→ 选分组 → 「开始(1)」→ 3 秒倒计时 → 跑步中。

| 步骤 | 断点 |
|---|---|
| 编辑器保存 | **P0-2**：表单约 3 屏长，保存按钮只在顶部；用户填完底部的「组循环/提示音」后必须滚回顶部。训练前的高频动作多了一次无意义滚动 |
| 开始按钮 | 「开始 (1)」中的 (1) 是分组数，无解释文案；但可接受 |
| 倒计时 | 全黑 + 灰字「即将开始」，无计划名/组信息上下文（P2-19） |
| 跑步中 | **P0-4**：卡片下方 ~50% 屏幕纯空。无下一段目标、无剩余时间、无组进度。跑步中低头 1 秒应获取「现在第几段 / 这段还剩几秒 / 下段多快」，当前只有当前段计时 |

### 流 2：400米模型 → 训练
首页 → 「400米模型」 → 输入 57.00 → 「生成计划」→ **直接跳落到「节奏跑」列表**，新分组出现在列表中。

| 步骤 | 断点 |
|---|---|
| 生成后落点 | **P0-3**：跨域跳转无任何成功反馈/说明。用户视角：点了生成，画面突然变成另一个功能的列表，新分组名被截断为「女子 400米 57.0...」。需要轻提示（toast/banner）+ 可选「查看计划」 |

### 流 3：停止训练
跑步中 → 「停止」→ 自绘确认弹窗「确定要停止训练吗？」→ 确定 → 回到设置页（历史已自动记录）。

- 确认弹窗样式与系统 Alert 区分度高，取消/确定位置符合预期。**良好**。
- 小问题：确认后落点回到「设置」tab（因为历史入口在设置里？）——实际是回到训练页；截图 08 流程验证落点为训练 tab，无问题。

### 流 4：语言切换
设置 → 语言设置 → 选择 → 完成，即时全局生效。功能正确；问题仅在上文导航模式不统一（P0-6）与双选中指示（P1-12）。

### 流 5：历史查看
底部 tab 直接展示统计卡 + 按日期分组列表，行内含类型色条、状态徽章、等宽时长。**结构良好**。缺页面大标题（与训练 tab 有大标题不一致，P1-13）。

## 4. 改进方案设计

> 原则（Linus 三问）：只修真实问题；优先用已有 DS 原语组合，不引入新框架；所有改动不破坏现有 UI 测试的 identifier 契约（只增不删）。

### Phase A —— P0 快赢（一次委派可完成，预计 1–1.5 天）

**A1 编辑器导航可达性**（问题 1）
- 所有「取消/保存/完成/返回/+」加 `.accessibilityLabel(...)` 与稳定 `.accessibilityIdentifier(...)`（沿用现有命名风格：`pace_editor_cancel_button` 等）。
- 验收：VoiceOver 可完成「新建节奏跑计划→保存」全流程；idb 能按 identifier 定位全部导航按钮；现有 UI 测试全绿。
- **实施修正**：编辑器导航按钮实为系统 toolbar 按钮（VoiceOver 本已可达，审计时的不可达是 idb axbridge 后端局限）。实际实施改为补充 `.accessibilityIdentifier`（`*_editor_cancel_button` / `*_editor_save_button` / `*_editor_save_bar_button`），并新增底部保存栏按钮的可测试标识。

**A2 编辑器底部固定保存栏**（问题 2）
- 编辑器（节奏跑/间歇跑/提示音）底部复用 `trainingPrimaryActionSurface` 加常驻「保存」主按钮（与「开始」栏同构），顶部保存保留（双入口无害）。
- 验收：不滚动任何页面即可保存；窄屏（SE 尺寸模拟器）不遮挡最后一个输入项。

**A3 生成计划成功反馈**（问题 3）
- 生成后停留原页，底部弹出轻提示条（复用卡片样式）：「已生成『女子 400米 57.00』并保存到节奏跑」+「查看」按钮；或跳转后自动展开该分组并 toast。实现取简：**停留 + 提示条**。
- 验收：生成后有明确成功反馈与去向说明；连续生成不重复堆叠提示。

**A4 训练中信息补全**（问题 4 + 5）
- 卡片下方增加一行「下一分段预告」：`下一段 · 50米 · 目标 7.5秒`；组循环时显示 `第 1/2 组`；间歇跑显示 `休息中 → 距下次跑步 12秒`（已有状态机，仅 UI）。
- 修复刻度尺最后标签裁切（右侧内缩 padding 或尾标签自适应宽度）。
- 验收：训练中单屏可读「当前段/剩余秒/下段目标/组进度」四要素；800米刻度完整显示。

**A5 设置子页导航统一**（问题 6）
- 统一为「即时生效 + 返回」（语言设置已是此模式）：提示音去掉 取消/保存 改即时保存 + 返回按钮（其内部本就有每项即时状态）。
- 验收：三个子页导航模式一致；无「保存了什么」的歧义。

**A6 首页与 tab 修正**（问题 9）
- `padding(.bottom, 100)` → 依据实际 tab 高度（约 120，含 safe area 动态计算），保证第 4 卡完整可滚出。
- 验收：iPhone 17 Pro 与 SE 模拟器上滚动到底第 4 卡完全离开 tab 遮挡。

### Phase B —— P1 视觉一致性（第二次委派，预计 1–2 天）

**B1 色彩令牌收口**（问题 7/8）
- `DS.Colors` 新增：`rest`（跑休冷色，暂定 teal 系）、`intensity`（强度琥珀）或规定强度=域主色；删除视图中全部 `.purple/.cyan/.indigo` 硬编码（grep 清零）。
- 编辑器区块图标底色统一规则：全部用域主色（如节奏跑编辑器所有 EditorCard 图标都是 paceRun），chip 选中色=域主色。
- 验收：grep 无 DesignSystem 外语义色；节奏跑编辑器一屏 ≤2 色相（主色+语义）。

**B2 语言/版本细节**（问题 12/13）
- 双选中指示去一（保留右对勾）；版本号改 SF 常规字重 + 本地化括号（`2.0 (4)`）。
- 验收：截图对照。

**B3 历史页标题**（问题 11）
- 顶部加与训练 tab 同构的大标题「历史记录」。
- 验收：两 tab 头部结构一致。

**B4 滚动页 nav 材质背景**（问题 10）

## 附录 B：无障碍专项

- 可达元素：首页卡片/tab、分组卡操作、GT 步进器、强度 chips、语言/登录入口均有 identifier 或标签——基础面尚可。

- 触控目标：全部 ≥44pt（暂停/停止/步进器实测通过）。
- 对比度：textHint(35% 白) 仅用于装饰文案合规；正文最低 textTertiary(55% 白) ≈ 4.6:1（黑底）达标。
